VoIP debugging playbook

Use this when a report says only “Phone does not work.” The goal is a first broken handoff with evidence.

1 · Freeze the context

  • Repository, branch and exact SHA.
  • Database, installed/updated addon and provider mode.
  • User, number, direction, approximate UTC time and sanitized event/order id.
  • Expected versus observed behavior.
  • Whether shared staging or any real carrier resource is involved.

2 · Name the lane

Wrong button, validation, state or RPCBrowser/Enterprise control planeRTP/audio debugging

Order changes in shop but not EnterpriseCallback/poll mirrorTelnyx search UI

Wrong/double/missing chargeTelnyx correlation → ledger → IAP key → cost lineAdding a retry before tracing stable keys

4 · Check the boundary contract

  1. Was the request sent?
  2. Was it authenticated for the intended client?
  3. Did the receiver persist a milestone?
  4. What response/status came back?
  5. Who owns retries?
  6. What stable key absorbs replay?
  7. Did later state mirror the committed result?
Security hygiene: never paste client secrets, account tokens, Wazo credentials, webhook tokens, carrier keys or customer audio into tickets, screenshots or agent prompts. Prefer ids, state names and redacted structural payloads.

5 · Choose the cheapest proof

  • Pure ORM/state branch: one Python model test.
  • JS calculation/component: one Hoot unit.
  • Browser integration: tour only when component tests cannot prove it.
  • Phone Service: model/controller test with explicit Telnyx/Wazo/IAP mocks.
  • Edge config: repository harness.
  • True SIP/media/carrier behavior: controlled shared-staging check after automated proof.

6 · Report the diagnosis
