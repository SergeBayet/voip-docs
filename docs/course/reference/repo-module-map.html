Inside core voip

Backend

models/ owns business state and the Phone Service/PBX facades; controllers/ owns browser/public HTTP boundaries; security/, data/ and views/ complete the addon contract.

Frontend

static/src/core/ integrates with Odoo web/mail; softphone/ owns call UX; flow_editor/ owns the Call Flow graph; widgets own reusable fields.

Tests

tests/ covers models, events, number lifecycle and PBX facade contracts. Frontend tests live beside static code or in the addon test tree.

Migrations

Stored-field/model meaning changes may require work in the separate Upgrade repository; a normal view or pure computed behavior change often does not.

Branch rule of thumb

“Master” and supported stable series are different product promises. Confirm the target with the team and current repository state. The current architecture treats the shared voip-common, phone-service-common, voip-boi and scheduled-call work as integrated foundations, while Enterprise, Community, IAP Phone Service, release automation and the SIP edge remain separate ownership boundaries. Never infer current remote, deployment or merge state from an old lesson.

Primary sources

Every addon's __manifest__.py; repository Git state; Odoo developer docs; the production files and tests named by the behavior.
