Data, views, actions & translations

Python supplies behavior; XML connects that behavior to the database and user interface.

⏱ 10 min🎯 Trace a menu to its model and data

XML is installation code

An XML <record> creates or updates a database record when the module loads. File order in the manifest matters: a referenced external ID must already exist. Use noupdate="1" only when an administrator should own later edits; it also means future module upgrades will not normally overwrite the record.

Views do not secure data

invisible, readonly and button visibility shape the experience. They are not authorization. Real protection comes from model access, record rules, field groups and server-side checks (next lesson).

Trace a real screen

Start at master/enterprise/voip/views/voip_provider_views.xml. Find its action and model, then locate the model in models/voip_provider.py and its access entry in security/ir.access.csv.

Translations are part of the feature

Write user-facing Python strings with _() and translatable XML normally; Odoo extracts them into PO catalogs. Do not build translated sentences by concatenating fragments—the translator needs the complete sentence and placeholders.
