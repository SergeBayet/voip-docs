ORM, recordsets & inheritance

A recordset is a smart batch of rows. Treating it as “one Python object” is the fastest route to slow or subtly wrong Odoo code.

⏱ 12 min🎯 Read and extend model code safely

The habits that matter

  • Assume self can contain many records unless ensure_one() is justified.
  • Batch reads and writes. A query inside a record loop is an N+1 query until proven otherwise.
  • Use relational fields and recordsets instead of passing raw IDs through domain code.
  • Declare every dependency a computed value reads with @api.depends.
  • Use a database constraint for race-safe uniqueness; use a Python constraint for richer cross-field rules.

Three kinds of extension

DeclarationMeaningUse
_name = "x.new"New model/table identityA new domain concept
_inherit = "res.users" without _nameExtend an existing model in placeAdd VoIP behavior to users
_name + _inheritNew model inheriting fields/behaviorReusable model specialization
Trace it in VoIP

Read voip_extension.py: models.Constraint("unique(number)", …) protects concurrent extension creation, while Python constraints explain invalid destinations. Then read res_users.py to see in-place model extension.

Learning edge: a pre-check such as “search, then create” is friendly but not race-safe. Two transactions can both see nothing. The database uniqueness guard is the final referee.
