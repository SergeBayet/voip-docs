Owl, services, registries & assets

The web client is a component tree with a toolbox: Owl renders state, services do shared work, and registries provide named extension points.

⏱ 12 min🎯 Place frontend behavior without fighting the framework

One responsibility per mechanism

MechanismUse it forAvoid
Owl componentLocal UI state, events and renderingGlobal singleton state hidden in a component
ServiceLong-lived shared capability or coordinationDirectly importing another service's internal state
RegistryNamed framework extension: field, action, view, serviceA custom switch statement duplicating a registry
PatchExtend code with no supported registry/subclass hookPatching when a documented extension point exists
Asset bundleLoad JS/XML/SCSS for the right client surfaceFiles that are never declared and therefore never load
Trace the softphone

static/src/core/web/voip_service.js registers the voip service and main components. static/src/softphone/dialer.js consumes it with useService("voip"). Their JS, XML and SCSS enter through bundles in voip/__manifest__.py.

Lifecycle in one sentence

Initialize hooks and services in setup(), derive rendering from reactive state, and clean up external listeners through lifecycle-aware hooks. Never use component constructors as an extension point.
