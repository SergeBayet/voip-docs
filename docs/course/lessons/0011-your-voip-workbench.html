Your VoIP workbench

You develop one local Odoo database against shared staging services. Know which boundary is local before blaming the wrong machine.

⏱ 12 min🎯 Choose the right module, environment and test

Start in the narrowest addon

voip

Core softphone, provider, users/extensions, numbers, PBX routing, calls, queues, flows, voicemail and sounds.

voip_ai

Recorded-call transcription and AI summary.

Integration addons

voip_crm, voip_helpdesk, voip_project, voip_sale, subscriptions, SMS, HR and recruitment.

Dashboard/storage addons

spreadsheet_dashboard_voip and voip_cloud_storage_google.

Two provider modes

Demo mode mocks call behavior so the UI is explorable without a PBX. It does not turn number purchase into fake data. Phone Service mode uses the real broker/edge/PBX integration and therefore needs the configured client identity, secret and shared environment.

Your first-day checks

  1. Verify Community and Enterprise baselines; use Enterprise master, not the historical Parrot feature branch.
  2. Install/update voip in a disposable database and open the softphone in demo mode.
  3. Run one Python test file and one filtered Hoot suite before changing code.
  4. Follow parrot-local-testing-guide.md before connecting to shared staging. Treat it as other people's infrastructure.
  5. Never paste secrets into logs, screenshots, lessons or commits.
