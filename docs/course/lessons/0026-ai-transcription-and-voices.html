AI: transcription & voices

Every call can write its own minutes, and every greeting can be spoken without a microphone — two AI-flavoured features that hang off the call log.

⏱ ~9 minutes🎯 Goal: know what gets transcribed, where it lands, and what triggers it🧩 Builds on: Lesson 23

Two very different features share this lesson because both wear an "AI" badge — but they live in different places and it is worth knowing which is which. One listens to calls and writes them down (voip_ai). The other speaks your greetings out loud (voip.sound, from Lesson 23). Keep them apart and you will never mis-answer the interview question "where does transcription live?"

Part 1 — Calls that write their own minutes

The one-liner. The auto-installed voip_ai module is a stenographer for your phone: it records each call, sends the audio to OpenAI Whisper to turn speech into text, and — when the whole call is transcribed — asks an AI agent for a one-line summary, then pings you "done".

The everyday picture

Imagine a court stenographer sitting quietly in every call, typing everything said. At the end they hand you a transcript and a sticky note with the gist ("Customer wants a refund on order 1042"). You did nothing; it just appears. That is voip_ai.

Where everything lands

voip_ai ("Phone - AI", depends: ["voip", "ai"], auto_install) extends voip.call with the call.transcription.mixin from the community ai module. The audio of a call is captured as a mail.call.artifact row; the transcript text is written back onto that same artifact.(voip_ai/models/voip_call.py)

⚠️ The aha: recording and transcript share one model. A recording and a transcript are both mail.call.artifact rows. The flag is_stt tells them apart — and a speech-to-text artifact deliberately does not light the "has a recording" icon in the call log. Same table, one boolean, two meanings.

On voip.call itself you will only find derived fields: a computed has_transcript, a transcription_state (pending → done/error), and the one-line summary. There is no raw transcript column on the call — always look on the artifact. When every artifact is done, an AI agent (voip_ai.voip_call_summary_agent) writes the summary and a bus notification tells the user "Transcription Completed".

It ships switched off

Nothing transcribes by default. An admin must set the provider's transcription_policy to "Force for all users" — which immediately checks that an OpenAI token exists (no token, clear error). That policy is handed to the browser softphone through res.users._get_voip_config → transcriptionPolicy, so the recorder only wakes up where it should.(voip_ai/models/voip_provider.py)

⚠️ Pocket gotcha: no cron backstop. Transcription is trigger-driven with no retry cron behind it. If the trigger is dropped, that artifact sits in pending forever — nothing sweeps it up later. If a call is stuck "Awaiting transcription", this is your first suspect.

Part 2 — Greetings that speak themselves

The other AI feature you already met in Lesson 23, and it is important to place it correctly: text-to-speech lives in the base voip module on voip.sound — NOT in voip_ai. Typing does not itself generate audio. The Generate action calls voip.sound.generate_tts_audio_preview(), which hands the text to the shop (PhoneServiceAPI.generate_speech), which returns audio synthesised by Telnyx. The voices are Telnyx voice ids, cached per day and filtered by language (matched to your res.lang) so the picker isn't one endless global list. The preview returns audio plus the text and voice used to generate it; saving requires matching generation metadata. Changing text or voice requires generating again. Saving then synchronizes the audio to the PBX in the current transaction, not through an after-commit callback.(voip/models/voip_sound.py)

Two AIs, two homes. Listening (speech → text) is voip_ai + OpenAI Whisper. Speaking (text → speech) is voip.sound + Telnyx, through the shop. If someone says "the AI module does our voices", gently correct them.
⌨️ Where this lives in our code

voip_ai/models/voip_call.py — the transcription mixin, has_transcript/transcription_state/summary, and the summary agent call.
voip_ai/models/voip_provider.py — transcription_policy and its OpenAI-token check.
voip/models/voip_sound.py — generate_tts_audio_preview() and the Telnyx voice catalogue, filtered by language. (TTS is base voip, not voip_ai.)

The Onboarding Guide §11.1 "AI call transcription" is the tight summary; then open voip_ai/models/voip_call.py and trace how transcription_state is computed from the artifacts — it makes the "same model, is_stt flag" point concrete.
