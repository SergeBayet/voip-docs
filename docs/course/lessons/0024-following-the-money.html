Following the money

Number purchase, monthly rent and call minutes use two different IAP shapes. Knowing which one you are in prevents expensive assumptions.

Do not merge these mental models. The new per-line IAP idempotency protects call-cost and monthly-fee ledger retries. Number purchase still uses a persisted classic authorization token. Its source explicitly records a known response-loss wedge after a successful capture.

How a nameless receipt finds its customer

Telnyx lifecycle events such as call.initiated carry the parties, direction and call_control_id. Phone Service stores a 12-hour correlation row. Later, call.cost carries that Telnyx id but no customer-facing parties, so the shop joins it to the row. If no client is resolvable yet, it returns 503 and lets Telnyx redeliver.

Only sip-trunking cost parts are billable. The shop applies the configured markup, rounds to four decimal places, drops a zero total, and renames the customer event to call_cost. The Enterprise callback uses the same client-scoped signed-token contract as the other Phone Service events—not an HMAC header.

Exactly once locally and remotely

1 · Event
UNIQUE(event_id)
2 · Ledger
UNIQUE(reference_type, reference_id)
3 · IAP server
UNIQUE(account, line key)

The ledger's remote line key is:

{client_uuid}:{reference_type}:{reference_id}

/iap/1/authorize_capture checks that key against both current and archived IAP transactions. A retry after “IAP charged, HTTP response was lost” therefore sees the settled key and skips it. This remote guard is the piece a database-only unique constraint cannot provide.

Call costs are post-paid: the shop passes allow_negative_balance=True. Those minutes already happened, so the charge must be recorded even if it takes the account below zero. The result marks the payment overdrawn; state reconciliation sets client.disabled, and the Kamailio edge consults that flag before admitting more trunk calls.

Delivery and charging can retry independently

The shop attempts the Enterprise forward, then stores and charges a fresh event. If Enterprise did not acknowledge, the shop returns 503 to Telnyx. A redelivery forwards again but hits the shop's existing event/payment keys, so it cannot charge twice. Failed IAP calls stay in the payment ledger; the 10-minute recovery cron retries with exponential backoff using the same remote key.

Enterprise bridges the second id gap

Telnyx's call_control_id never reaches the Wazo/Odoo call record. Enterprise therefore matches a cost line by direction, the other party's normalized number and a time window. If several calls match, it chooses the nearest call end and logs a warning. Unmatched lines remain valid accounting records; a cron rechecks recent orphans for two hours because the cost can arrive before the call row.
